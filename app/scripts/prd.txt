# 장애인 복지 AI 챗봇 백엔드 리팩토링 PRD

## 목표
- 챗봇 API 서버가 본연의 역할(대화, 전문가 응답, 분석 등)에 집중하도록 코드 구조를 정리한다.
- 데이터 임베딩, 크롤링, 대량 적재 등은 별도 서비스/스크립트로 분리한다.
- 불필요하거나 중복, 충돌이 발생하는 코드를 제거한다.

## 주요 요구사항

1. **챗봇 API 서버의 역할 정의 및 문서화**
    - 대화, 전문가 응답, 분석 등 실시간 사용자 요청에 대응하는 코드만 유지
    - 역할 및 책임을 명확히 문서화

2. **service/ 디렉토리 내 임베딩/크롤링/데이터 적재 코드 분리**
    - embedding.py, embedding_job.py, embedding_jobseekers.py, embedding_welfare.py 등은 별도 디렉토리(예: scripts/ 또는 data_processing/)로 이동
    - 챗봇 API 서버에는 포함하지 않음

3. **mongodb.py 역할 분리 및 정리**
    - 챗봇 응답에 필요한 함수만 남기고, 데이터 적재/상세조회/구직현황 등은 별도 데이터 서비스로 분리

4. **scripts/ 내 크롤링, 데이터 업로드, 정책 데이터 가공 코드 완전 분리**
    - FastAPI 챗봇 서버에서 완전히 분리, 별도 실행/배포

5. **main.py 내 임시/테스트 엔드포인트 제거**
    - /mongo-test 등 운영과 무관한 엔드포인트는 삭제

6. **분리된 코드의 별도 실행/배포 환경 구성**
    - 데이터 처리/크롤링/임베딩 코드는 별도 스크립트/마이크로서비스로 관리

7. **최종 구조 및 역할별 문서화**
    - 디렉토리 구조, 각 모듈/서비스의 역할을 문서화
